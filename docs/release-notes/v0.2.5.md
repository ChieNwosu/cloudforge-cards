# Release Notes: v0.2.5 (Scoring Fairness Release)

**Live Demo:** [https://cloudforge-cards.emergent.host/](https://cloudforge-cards.emergent.host/)

**Release Date:** June 2025

---

## Summary

CloudForge Cards v0.2.5 is the Scoring Fairness Release. The scoring engine was rewritten for transparency, fairness, and explainability. The app is now deployed and publicly accessible.

---

## What Changed

### Scoring Fairness Rewrite

- Six sub-scores replace the previous opaque scoring system
- Each sub-score has a clear max point value and description
- Guardrails ensure ideal architectures always score at least 85
- Full ideal match with one reasonable extra service scores at least 78
- Synergy detection rewards well-known AWS service pairings
- Rating tiers clearly map score ranges to architecture quality labels

### How to Play Sync

- How to Play screen updated to reflect the new six-category scoring model
- Explanation bonus (up to 5 points) is now documented in the How to Play section
- Scoring tier labels are explained for players

### Deployed Manual QA

- Full 3-round solo run verified on the live deployment
- All six scoring categories display correctly per round
- Final game summary, leaderboard save, and leaderboard lookup confirmed working
- Screenshots captured and added to `docs/screenshots/v0.2.5/`

---

## Screenshot Note

The screenshots in `docs/screenshots/v0.2.5/` show a manual QA solo run. The different scores across rounds are test examples demonstrating how the scoring system handles partial fits, full matches, and weak selections. They should not be interpreted as a formal assessment of the creator's AWS knowledge.

---

## Known Minor Issues

- **"Not core to scenario" feedback placement:** This feedback can appear under "What You Got Right" when it should appear under "What to Improve." The scoring correctly penalizes these selections, but the UI placement is misleading. Fix planned for v0.2.6.

---

## Final QA Status

- Backend scoring acceptance tests pass (5 test cases covering ideal, partial, and distractor selections)
- Manual 3-round QA checklist completed against the live deployment
- No blocking issues found
