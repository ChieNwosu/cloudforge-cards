# EC2 (Elastic Compute Cloud)

## Summary

EC2 provides resizable virtual machines (instances) in the cloud. You choose the operating system, instance type, storage, and networking configuration. EC2 is the most flexible compute option in AWS but requires more operational management than serverless alternatives.

## Key Concepts

### Instance Types

AWS organizes instances into families optimized for different workloads:
- **General Purpose (t3, m5):** Balanced compute, memory, and networking. Good default choice.
- **Compute Optimized (c5):** High-performance processors. Batch processing, gaming servers.
- **Memory Optimized (r5, x1):** Large in-memory datasets. Databases, caching.
- **Storage Optimized (i3, d2):** High sequential read/write to local storage. Data warehousing.
- **Accelerated Computing (p3, g4):** GPUs for machine learning, graphics rendering.

### Pricing Models

- **On-Demand:** Pay by the second with no commitment. Most flexible, highest per-unit cost.
- **Reserved Instances:** 1 or 3 year commitment for significant discount (up to 72%). Predictable workloads.
- **Spot Instances:** Bid on unused capacity at up to 90% discount. Can be interrupted with 2-minute notice.
- **Savings Plans:** Flexible commitment to a consistent amount of compute usage (measured in $/hour).
- **Dedicated Hosts:** Physical servers dedicated to your use. Compliance or licensing requirements.

### Key Features

- **Security Groups:** Virtual firewalls controlling inbound and outbound traffic at the instance level
- **Key Pairs:** SSH keys for secure login to Linux instances
- **Elastic IP:** Static public IPv4 address you can attach/detach from instances
- **User Data:** Scripts that run automatically at instance launch for bootstrapping
- **AMI (Amazon Machine Image):** Template containing the OS, application server, and applications

### Auto Scaling

Automatically adjusts the number of EC2 instances based on demand. Ensures you have the right amount of compute at all times. Works with CloudWatch alarms to trigger scaling events.

### Elastic Load Balancing

Distributes incoming traffic across multiple EC2 instances:
- **ALB (Application Load Balancer):** Layer 7, HTTP/HTTPS, path-based routing
- **NLB (Network Load Balancer):** Layer 4, ultra-low latency, TCP/UDP
- **CLB (Classic Load Balancer):** Legacy, both Layer 4 and Layer 7

## CloudForge Cards Integration Ideas

- EC2 is a Compute category card with high cost (4) and moderate complexity (3)
- EC2 is often a distractor in scenarios where serverless solutions are more appropriate
- The "Serverless" constraint chip penalizes architectures that use EC2 unnecessarily
- Synergy pairs: EC2+EBS, EC2+ALB, EC2+RDS

## Related Service Cards

- EC2 (Compute, cost: 4, serverless: false)
- EBS (block storage for EC2)
- ALB (load balancing across EC2 instances)
- Auto Scaling (not a separate card, but implied by EC2 architecture)

## Potential Scenario Ideas

- "Legacy Monolith Hosting": A traditional three-tier application that genuinely needs OS-level control. EC2 is the right answer here.
- "Batch Video Processing": CPU-intensive transcoding jobs that run for hours. Spot instances offer massive cost savings.
